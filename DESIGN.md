## 1. Продукт, аудитория, тон

- **Продукт:** DIAMONDS — имиджевый лендинг (сайт-визитка) ювелирного бренда. Без CMS, без внешних сервисов, без аналитики; весь контент — в локализационных модулях репозитория.
- **Аудитория:** частные клиенты, рассматривающие премиальные украшения; потенциальные партнёры. Первый визит, экран десктоп и мобильный.
- **Задача страницы:** сформировать образ бренда, кратко рассказать о ценностях и коллекциях, дать честный тестовый канал связи.
- **Тон:** сдержанный, премиальный, светящийся, а не «кричащий».
- **Честность контента:** запрещены неподтверждённые заявления — фейковые цифры, награды, отзывы, «№1 на рынке», имитация соцдоказательств. Форма контактов везде маркируется как тестовая (§8).

## 2. Визуальная концепция

**Направление: «Brilliance in the dark»** — глубокая тёмная база (витрина ночью), свет живёт в кристалле, типографике и акцентах. Тёмная тема фиксирована и единственно допустима в v1 (переключатель темы не входит в объём). Токены устроены как CSS-переменные, поэтому светлая тема может быть добавлена позже заменой значений без изменения разметки.

### 2.3 Поверхности, границы, радиусы, тени

- Границы: `1px solid ink-700`. Разделители секций — линии, не «карточки в карточках».
- Радиусы: `sm 6px` (кнопки, поля), `md 10px` (панели, ячейки), `pill 999px` (бейджи).
- Тени минимальны; «свечение» — только у кристалла: `0 0 60px rgba(143,216,255,0.18)`.
- Плотность: воздушная. Секции `py-16` (mobile) → `py-24` (lg). Сетки `gap-6`/`gap-8`. Контент `max-width: 1120px`, текстовые колонки — не шире 34rem.

### 2.4 Состояния интерактивных элементов

- **Кнопка primary:** фон `ice-300`, текст `ink-950`; hover `ice-200`; active — `transform: scale(0.99)` (в reduce-режиме — мгновенно); disabled — `opacity 0.55`, `cursor: not-allowed`.
- **Кнопка secondary / ссылки-обёртки:** прозрачный фон, граница `ink-700`, текст `cloud-50`; hover — граница `ice-300`.
- **Ссылки в тексте:** `ice-300`, underline с `text-underline-offset: 3px`; hover `ice-200`.
- **Поля ввода:** фон `ink-900`, граница `ink-700`, текст `cloud-50`, плейсхолдер `cloud-400`; focus — граница `ice-300` + кольцо `2px rgba(143,216,255,0.35)`; error — граница `negative-400` + сообщение под полем.
- Все интерактивные цели ≥ 44×44px.

### 2.5 Графика

- Только SVG (кристалл, иконки 24×24, stroke 1.5, `aria-hidden="true"`). Никаких растровых изображений, стоков и внешних ассетов — репозиторий самодостаточен.

## 4. SVG-кристалл: структура и анимация

**Компонент `CrystalLogo` — чистый SVG + CSS.** React только рендерит разметку. Анимация не зависит от JavaScript: работает при SSR, нет мерцания/сдвига вёрстки (заданы `width`/`height`/`aspect-ratio`), нет «JS-артефактов». Исполняется на обеих языковых версиях одинаково.

### 4.1 Структура SVG (`viewBox="0 0 240 240"`)

1. `<defs>`: `linearGradient#crystal-ice` (`#EAF6FF` 0% → `#8FD8FF` 35% → `#4E7CF6` 70% → `#B388FF` 100%), `radialGradient#crystal-glow` (`#8FD8FF` → transparent 70%).
2. `circle.crystal__glow` — радиус ≈110, за фигурой, анимируется только `opacity` (никаких SVG-фильтров/blur — дорого и ненадёжно).
3. `g.crystal__body` — силуэт бриллианта: таблица (верхняя площадка), корона, павильон (3–4 полигона), заливка градиентом, обводка `rgba(234,246,255,0.35)` 1px.
4. `g.crystal__facets` — 6–8 фасет-полигонов с фиксированной `fill-opacity` 0.12–0.55.
5. `g.crystal__sparkles` — 3 `circle` r 2–3 (декор, `aria-hidden`).

Доступность: у `<svg>` — `role="img"` и локализованный `<title>` из словаря (`aria-label` дублировать не нужно); спарклы и glow — `aria-hidden="true"`.

### 4.2 Схема анимации (CSS-кейфреймы)

| Имя | Свойства | Ключевые кадры | Duration | Easing | Итерации / задержки |
|---|---|---|---|---|---|
| `crystal-float` | `transform: translateY` | `0 → -10px` | 6s | `ease-in-out` | infinite, `alternate` |
| `crystal-tilt` | `transform: rotate` | `0 → 3deg → 0` | 14s | `ease-in-out` | infinite |
| `crystal-shimmer` | `opacity` (фасеты) | `0.15 → 0.5` | 3.6s | `ease-in-out` | infinite, `alternate`; стаггер-задержки `0 / 0.6 / 1.2 / 1.8s` по фасетам 1–4 |
| `crystal-sparkle` | `opacity`, `transform: scale` | `0/0.6 → 1/1.1 → 0/0.6` | 2.8s | `ease-out` | infinite; задержки `0.4 / 1.5 / 2.4s` |
| `crystal-glow-pulse` | `opacity` | `0.25 → 0.45` | 5s | `ease-in-out` | infinite, `alternate` |

Правила реализации:

- Анимируются **только** `transform` и `opacity` (композитор-безопасно). Запрещено анимировать `filter`, `width`, `d`, `box-shadow`.
- Для SVG-групп: `transform-box: fill-box; transform-origin: 50% 55%`.
- Keyframes — в `globals.css`, маппинг — `theme.extend.animation` Tailwind (`animate-crystal-float` и т. п.) либо классы компонента; выбирает `app_bootstrap`, синтаксис кейфреймов фиксирован этой таблицей.
- Мигание (мерцание контраста) не быстрее 3 Гц — фоточувствительность.
- `will-change` не требуется; `prefers-reduced-motion` соблюдается строго (§5).

### 4.3 Почему CSS, а не SMIL

SMIL (`<animate>`, `<animateTransform>`) **игнорирует** `prefers-reduced-motion` и требует JS для остановки. CSS-анимации честно отключаются media-запросом без единой строки JS, работают при SSR. SMIL в v1 запрещён.

## 5. `prefers-reduced-motion: reduce`

Поведение: **полное отключение движения, мгновенные состояния покоя**, контент полностью доступен (ничего не скрывается и не заменяется).

Реализация — только CSS (в `globals.css` и стилях кристалла):

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation: none !important;
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
  }
  /* мгновенные состояния покоя кристалла */
  .crystal__body   { transform: none; }
  .crystal__facet  { opacity: 0.32; }   /* нейтраль между 0.15 и 0.5 */
  .crystal__sparkle{ opacity: 0.5; transform: none; }
  .crystal__glow   { opacity: 0.35; }
}
```

- JS `matchMedia` **не нужен** и не должен дублировать логику (единственный источник правды — CSS).
- Мгновенные состояния: hover/active/focus меняются без переходов; якорная прокрутка — мгновенная.
- Проверка: DevTools → «Emulate prefers-reduced-motion: reduce» на обеих языковых версиях + скриншот-чек по §9.

## 6. Доступность

- **Структура:** семантические landmarks (`header` / `main` / `footer`), один `h1` (hero), секции — `<section aria-labelledby>` с заголовками без пропусков уровней.
- **Skip-link** «Перейти к содержимому / Skip to content» → `#main`, видим при фокусе.
- **Фокус:** `:focus-visible` — контур `2px solid ice-300` + `offset 2px`; контуры не удаляются нигде; порядок DOM = порядок визуального чтения; ловушек фокуса нет.
- **Форма (§8):** явные `<label for>`; обязательность текстом («(обязательно)»), не только цветом; `aria-required`; при ошибке — `aria-invalid="true"` и `aria-describedby` с текстом ошибки; область статуса — `role="status"` + `aria-live="polite"` (подтверждение и сетевые ошибки); фокус на первое невалидное поле при неуспешной отправке.
- **Кристалл:** `role="img"` + локализованный `<title>` (§4.1).
- **Языковой переключатель:** `<nav aria-label="Language">`, ссылки (не кнопки) с видимыми подписями «Русский / English», активный язык — `aria-current="true"`.
- **Контраст (WCAG 2.1 AA):** body ≥ 4.5:1, крупный текст ≥ 3:1, границы/фокус UI ≥ 3:1.

| Пара (前景/背景) | Расчётный контраст | Требование |
|---|---|---|
| `cloud-50` на `ink-950` | ~17:1 | AAA |
| `cloud-300` на `ink-950` | ~8:1 | AAA |
| `cloud-400` на `ink-950` | ~4.6:1 | AA (минимум) |
| `ice-300` на `ink-950` | ~11:1 | AAA |
| `ink-950` на `ice-300` (primary-кнопка) | ~11:1 | AAA |
| `negative-400` на `ink-900` | ~5:1 | AA |

Значения **расчётные**; задача `integration_verify` обязана подтвердить их инструментом на рендере и исправить токены при расхождении.

## 7. Локализация RU/EN

### 7.1 Структура модулей

```
src/i18n/
  config.ts          # locales = ['ru','en'] as const; type Locale; defaultLocale = 'ru'
  types.ts           # интерфейс Dictionary (общий для обоих языков)
  dictionaries/ru.ts # const ru: Dictionary
  dictionaries/en.ts # const en: Dictionary
  index.ts           # getDictionary(locale) — статические импорты, без i18n-библиотек
```

- Словари — типизированные константы; ключи сгруппированы по секциям: `nav`, `hero`, `about`, `values`, `advantages`, `contacts`, `form`, `footer`, `a11y`.
- **Хардкод пользовательских строк в компонентах запрещён.** Вся типографика строк — из словарей; проверка `grep` в §9.
- Межъязыковая согласованность: `Dictionary` гарантирует одинаковый набор ключей для RU и EN (компиляция не пройдёт при расхождении).

### 7.2 Маршрутизация

- `app/[locale]/layout.tsx` — `generateStaticParams` → `['ru','en']`, рендерит `<html lang={locale}>`, общий header/footer.
- `app/[locale]/page.tsx` — контентная страница (обе языковые версии одной реализацией).
- `app/page.tsx` — `redirect('/ru')`.
- `app/api/contact-test/route.ts` — API формы, не локализуется по маршруту (сообщения UI — из словарей).
- `generateMetadata`: `title`/`description` из словаря, `alternates.languages` с `hreflang` для `/ru` и `/en`.

### 7.3 Переключатель языка (сохранение раздела)

- `LocaleSwitcher` — client-компонент: берёт `window.location.hash` и формирует ссылку `/${targetLocale}${hash}` → при смене языка пользователь остаётся в текущей секции.
- На SSR/без hash — ссылка без якоря (грейсфол fallback, без ошибок гидратации).
- Идентификаторы секций межъязыково идентичны (§3) — иначе hash не найдёт секцию.

## 8. Контактная форма: UI-контракт

Реализация — задача `test_form`; здесь зафиксированы визуальное поведение и контракт.

- **Поля (все обязательные):** имя, email, сообщение.
  - `name`: trim, 2–100 символов;
  - `email`: базовая проверка формата, ≤ 254 символов;
  - `message`: trim, 10–2000 символов.
- **Маркировка тестового режима:** бейдж `warning-400` «Тестовый режим / Test mode» рядом с заголовком формы + пояснение: «Данные не сохраняются и не отправляются — форма работает только в тестовом режиме» (оба языка, из словаря). Никакой имитации реальной отправки.
- **Состояния UI:**

| Состояние | Поведение |
|---|---|
| idle | кнопка активна, подсказки на месте |
| touched / invalid | inline-ошибка под полем, `aria-invalid`, текст из словаря |
| submitting | кнопка disabled, `aria-busy="true"`, текст «Отправка… / Sending…» |
| success | подтверждение в `aria-live`-области, форма очищается |
| error-validation (сервер 400) | inline + сводка ошибок из ответа |
| error-network | честное сообщение «Сервис недоступен, попробуйте позже / Service unavailable» — **без** фейкового успеха |

- **API-контракт:** `POST /api/contact-test`, JSON `{name, email, message}`:
  - `200` → `{ok: true, test: true}`;
  - `400` → `{ok: false, errors: {field: string[]}}` при невалидном payload;
  - без сохранения, без логирования персональных данных, без внешних вызовов.
